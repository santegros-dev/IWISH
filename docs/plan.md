# IWISH: план продукта (черновик v2, 29.09.2026)

## 1. Принятые решения
| # | Вопрос | Решение |
|---|--------|---------|
| 1 | Платформы | Сначала сайт (адаптивный под телефон). Приложения Android/iOS потом, на общей кодовой базе |
| 2 | Гости | Без обязательной регистрации: имя + метка в браузере. По желанию вход через Telegram или почту, чтобы видеть брони с другого устройства |
| 3 | Что видит автор | Только «подарок занят», без имени того, кто занял |
| 4 | Ссылки автора | Превращаем в партнёрские, где это возможно |
| 5 | Доход | Партнёрские комиссии, позже рекламные баннеры. Для пользователей бесплатно |
| 6 | ИИ-модель | Пока не выбрана. Делаем сменной: вся работа с ИИ идёт через один модуль-адаптер, модель меняется настройкой |
| 7 | Самозанятость | Пока нет. Оформим, когда сервис покажет, что он нужен людям |
| 8 | Что видят гости | Все подарки со статусом «свободно» / «занято», без имён. Занятый забронировать нельзя |

## 2. Роли
- **Автор**: создаёт вишлист. Регистрация обязательна (Telegram или почта), иначе он потеряет свой список.
- **Гость**: открывает список по ссылке, бронирует подарки. Регистрация не нужна.
- **Администратор** (Ilia): модерация, статистика, настройки партнёрок.

## 3. Основные сценарии (MVP)

### Автор
1. Входит через Telegram или почту (одноразовый код / magic link).
2. Создаёт вишлист: повод (день рождения, Новый год, свадьба…), дата события, короткий текст о себе и своих увлечениях.
3. Добавляет подарки: вставляет ссылку на товар → сервис подтягивает название, картинку и цену. Если не получилось, автор вводит вручную. Можно добавить подарок без ссылки («сертификат в книжный»).
4. Получает ссылку вида `iwish.ru/w/k7Fq2x` и отправляет гостям. Красивое превью ссылки в Telegram/WhatsApp/VK.
5. Видит список со статусами «свободно» / «занято». Кто занял, не видит.
6. Может редактировать и удалять подарки. Если удаляет забронированный подарок, гость получает предупреждение.

### Гость
1. Открывает ссылку, видит список и описание интересов автора.
2. Нажимает «Забронирую» → при первом разе вводит имя (его видит только сам гость и администратор, другие гости и автор видят лишь «занято»). Браузер запоминает гостя.
3. Забронированный подарок становится «занят» для всех. Второй раз забронировать нельзя.
4. Снять бронь может только тот, кто бронировал.
5. При повторном заходе видит отметку «Вы забронировали».
6. По желанию привязывает Telegram или почту, чтобы брони были видны на другом устройстве и чтобы не потерять их при очистке браузера.
7. Раздел «Подобрать другой подарок»: ИИ предлагает 6–10 идей на основе интересов автора, каждая со ссылкой на товар (партнёрской). Гость может забронировать идею, и она добавляется в список как «подарок от гостя» (автор видит его как «занятый подарок» без имени).

## 4. Экраны сайта (MVP)
1. Лендинг: что это, кнопка «Создать вишлист».
2. Вход (Telegram / почта).
3. Мои вишлисты (автор).
4. Редактор вишлиста: повод, дата, интересы, подарки.
5. Добавление подарка (вставка ссылки + предпросмотр).
6. Публичная страница вишлиста (гость): список, брони, блок «Идеи от ИИ».
7. Мои брони (гость): все брони во всех вишлистах.
8. Админка: пользователи, вишлисты, клики и доход по партнёркам.

## 5. Как узнаём гостя
- При первом бронировании создаётся анонимный гость: случайный токен в httpOnly-cookie (на год) + имя.
- Бронь привязана к гостю. Кнопка «Снять бронь» видна только тому же гостю.
- Опционально гость привязывает Telegram или почту → появляется аккаунт, брони переносятся к нему, и он видит их на любом устройстве.
- Если гость потерял cookie и не привязал аккаунт, бронь снять сам не сможет. Решение: письмо/сообщение в Telegram со ссылкой-ключом при бронировании (если указан контакт), либо автор может «освободить» подарок вручную (без раскрытия имени).
- Защита от ботов и спама: ограничение частоты бронирований, невидимая капча.

## 6. Партнёрские ссылки: что удалось выяснить
- **Ozon**: есть программа Ozon Blogger (для самозанятых, процент от продаж, у Ozon сказано «до 50%»), маркировка рекламы происходит автоматически. Нужно проверить, пускают ли туда сайты, а не только блогеров. Источники: [ozon.ru/bloggers](https://www.ozon.ru/bloggers), [corp.ozon.ru](https://corp.ozon.ru/ru/sth/ozon-zapuskaet-referalnuyu-programmu-dlya-blogerov-68390eb8).
- **Wildberries**: собственная монетизация через Wibes ориентирована на контент внутри их приложения (около 5%). Для сайтов есть программы через Admitad / Takprodam (до 9%), но это программы отдельных продавцов, а не всего WB: не каждый товар даст комиссию. Источники: [admitad WB](https://www.admitad.ru/store/offers/wildberries-affiliate-program/), [affelist.ru](https://affelist.ru/stati/referalnye-programmy-marketplejsov/).
- **Яндекс Маркет**: партнёрская программа до 25%, нужна регистрация самозанятого, ИП или ООО. Источник: [affelist.ru](https://affelist.ru/stati/referalnye-programmy-marketplejsov/).
- **AliExpress**: партнёрка через Admitad и собственный портал, с поиском товаров по API (удобно для ИИ-подбора). Нужно проверить текущие условия.
- **Маркировка**: партнёрские ссылки в РФ считаются рекламой, нужен erid через ОРД. CPA-сети и Ozon делают это сами; при прямой работе делаем сами.
- **Вывод**: для выплат нужна самозанятость или ИП. Пока их нет, запускаем сервис без партнёрок: все ссылки уже идут через наш редирект, поэтому после оформления партнёрки включаются без изменений для пользователей. Технически делаем модуль «конвертер ссылок»: на входе ссылка магазина, на выходе партнёрская (или исходная, если программы нет). Правила для каждой площадки подключаются отдельно, так что можно стартовать с 1–2 площадками.
- **Важно**: переход по ссылке идёт через наш редирект `iwish.ru/go/<id>`, чтобы считать клики и менять партнёрку без правки старых ссылок.

## 7. ИИ-подбор подарков
1. Из описания интересов автора языковая модель формирует 8–10 идей подарков с поисковыми запросами и ценовым диапазоном.
2. По каждому запросу ищем реальные товары в каталогах, где есть партнёрка и API/фиды (AliExpress, товарные фиды из Admitad, Яндекс Маркет).
3. Показываем гостю карточки с картинкой, ценой и партнёрской ссылкой. Результаты кэшируем на сутки для каждого вишлиста, чтобы не платить за каждый показ.
4. Фильтр гостя: бюджет («до 3000 ₽»).
- **Сменная модель.** В коде есть один интерфейс «ИИ-провайдер» (сгенерировать идеи по интересам). Под него пишутся адаптеры: YandexGPT, GigaChat, Claude, GPT и т.д. Какой используется, задаётся настройкой в админке или конфиге, без переписывания кода. Промпты хранятся отдельно от кода, ответы модели проверяются по единой схеме (JSON), чтобы любая модель выдавала одинаковый формат.
- Для разработки можно начать с любой доступной модели; на запуске сравним 2–3 модели на одних и тех же описаниях интересов и выберем.

## 8. Архитектура и стек (рекомендация)
- **Сайт + сервер**: Next.js (TypeScript). Серверный рендеринг нужен для превью ссылок в мессенджерах и для поисковиков.
- **База**: PostgreSQL.
- **Хостинг**: в России (Yandex Cloud или Selectel): по 152-ФЗ персональные данные россиян нужно хранить в РФ.
- **Вход**: Telegram Login + вход по коду на почту.
- **Мобильные приложения (этап 3)**: React Native (Expo) на том же TypeScript и том же API. Альтернатива на первое время: PWA (сайт, который ставится на экран телефона).
- **Фоновые задачи**: подтягивание карточек товаров, обновление цен, генерация ИИ-идей.

### Модель данных (набросок)
- `users` (авторы и гости с аккаунтом), `guests` (анонимные гости: токен, имя, ссылка на user при привязке)
- `wishlists` (автор, повод, дата, интересы, публичный код ссылки)
- `gifts` (вишлист, название, исходная ссылка, партнёрская ссылка, картинка, цена, источник: автор / ИИ / гость)
- `reservations` (подарок — уникально, гость, время). Уникальный индекс на подарок гарантирует «одна бронь на подарок» даже при одновременных нажатиях.
- `clicks` (переходы по партнёрским ссылкам), `ai_suggestions` (кэш идей)

## 9. Юридическое
- Политика конфиденциальности и согласие на обработку персональных данных (152-ФЗ).
- Маркировка рекламы (erid) для партнёрских ссылок и позже баннеров.
- Самозанятость или ИП для получения выплат от партнёрок.
- Пользовательское соглашение.
