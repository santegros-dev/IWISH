# IWISH

Сервис вишлистов: автор составляет список желаемых подарков со ссылками на маркетплейсы и делится ссылкой, гости бронируют подарки. Позже: ИИ-подбор подарков по интересам автора и партнёрские ссылки.

План продукта: [docs/plan.md](docs/plan.md).

## Что уже работает (этап 1)

- Вход автора по коду на почту или через Telegram.
- Вишлисты: название, повод, дата, описание интересов.
- Подарки: ссылка на товар (название, картинка и цена подтягиваются, если магазин отдаёт их), комментарий, цена.
- Публичная страница по ссылке `/w/<код>`: гости бронируют без регистрации, одна бронь на подарок, снять бронь может только тот, кто бронировал. Автор видит только «занят», без имени.
- «Мои брони»: гость узнаётся по cookie в браузере, а после входа видит брони с любого устройства.
- Все ссылки на магазины идут через `/go/<id>`: считаются переходы, позже здесь подключатся партнёрские ссылки (`src/lib/affiliate`).

## Стек

Next.js 16 (App Router, Server Actions), TypeScript, Tailwind CSS 4, PostgreSQL + Drizzle ORM, Vitest.

## Запуск локально

```bash
cp .env.example .env          # настройки
docker compose up -d          # PostgreSQL (или своя база, см. DATABASE_URL)
npm install
npm run db:migrate            # создать таблицы
npm run dev                   # http://localhost:3000
```

Без `SMTP_URL` код для входа печатается в лог сервера.

## Проверки

```bash
npm run lint
npm run typecheck
npm test        # нужна база iwish_test (TEST_DATABASE_URL), тесты сами создают таблицы
npm run build
```

## Структура

- `src/db/schema.ts` — таблицы базы; миграции в `drizzle/` (`npm run db:generate` после изменения схемы).
- `src/lib/` — логика без привязки к страницам: вишлисты и брони (`wishlists.ts`), вход (`login-codes.ts`, `telegram.ts`, `sessions.ts`), гости (`guest-store.ts`), ссылки (`links.ts`, `affiliate/`).
- `src/app/` — страницы и Server Actions.
- `tests/` — тесты логики на реальной базе.
